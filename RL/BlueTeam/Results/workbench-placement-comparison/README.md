# Archived workbench comparison

`bundle.json.gz`, `manifest.json` and `protocol.json` are the published native
capture from 23 September 2026. They retain all three archived RL layouts and
three predeclared scenarios. These results were not regenerated by the later
training-exploration changes.

`source-snapshot/` preserves the exact twelve source files identified by the
capture protocol's `sourceSha256` map. They are historical evidence, not modules
used by the current application. Do not import, build or edit them as current
implementation files.

The source bytes were recovered from Git commit
`2aaf7b698087646a084afc435879df97a80a6ea6`. Every recovered file matches its
original published SHA-256. `source-snapshot.json` also records the recovery
commit, Git blob IDs, byte counts, and the unchanged manifest and bundle hashes.
The protocol's earlier `baseCommit` records HEAD at capture time; its per-file
hashes identify the actual source bytes. The recovery commit is not presented as
the capture-time HEAD.

The regression check verifies these frozen source bytes against the original
protocol, rather than expecting evolving training code to remain byte-identical
forever. The repository's `* -text` Git attribute preserves the evidence bytes
across operating systems. No Git history is required to verify a source archive.

To publish results from a changed implementation, run a new native capture and
retain its own protocol and source evidence. Do not update these historical
hashes merely to match current code.
